playwright-interactive を使って、ゼロからブラウザで動く three.js の FPS風エイム訓練場アプリを作ってください。

前提:
- GitHub CLI (gh) は認証済みです
- GitHub リポジトリの新規作成から始めてください
- 作業ディレクトリは 現在の作業用ルートディレクトリ配下に作成して使ってください
- リポジトリを clone / 作成して問題ありません
- 最終的に GitHub Pages にデプロイし、公開URLを Playwright で実際に確認してください
- GitHub Pages へのデプロイは手動ではなく、CI/CD で自動化してください
- ユーザーによる手動操作を前提にせず、ローカル版・公開版ともに Playwright によるブラウザ操作で functional QA と visual QA を実施してください
- 確認できなかった項目は、確認済みとして報告しないでください

作るもの:
- three.js を使ったブラウザ動作の FPS風エイム訓練場 Web アプリ
- 起動後すぐに遊べること
- 一人称視点で訓練場内を移動できること
- WASD 移動、マウス視点変更、Space ジャンプ、Shift ダッシュに対応すること
- 中央クロスヘアを表示すること
- 左クリックでターゲットを撃ち、命中判定を行うこと
- 静止ターゲット、移動ターゲット、ポップアップターゲットを実装すること
- 命中数、ミス数、命中率、平均反応時間、スコア、コンボ、FPS を HUD に表示すること
- 制限時間つきチャレンジと自由練習モードを実装すること
- 難易度を変更できること
- ウィンドウリサイズ時に canvas と HUD が崩れないこと
- ブラウザのみで動作し、サーバーサイド処理は不要とすること

安全性・表現方針:
- 実在の銃器名、実銃の詳細な再現、実戦的な戦術訓練を主目的にしないでください
- 武器表現は抽象的な「クリック発射」「エネルギービーム」「スポーツ的ターゲットヒット」程度にしてください
- 人型ターゲットや暴力的な演出は避け、円形・立方体・ホログラム的な的を使ってください
- 流血、負傷、敵キャラクター、対人戦、軍事訓練を連想させる演出は入れないでください
- 目的はゲーム的な反応速度・ポインティング精度・視点操作練習としてください

訓練場の仕様:
- SF風またはスポーツ施設風の3D訓練場にしてください
- 床、壁、柱、障害物、的の出現エリアを配置してください
- プレイヤーが移動できる範囲を明確にしてください
- 壁や障害物をすり抜けにくいようにしてください
- 落下や場外に出た場合は自動で初期位置へ戻してください
- 訓練場内に複数のターゲット出現ポイントを用意してください
- 的は視認しやすい色・発光・輪郭で表現してください
- 命中時には短いエフェクト、音なしでも分かる視覚フィードバックを出してください
- ミス時にも HUD にミス数が反映されるようにしてください

操作仕様:
- WASD: 移動
- Mouse move: 視点変更
- Left click: ターゲットを撃つ / 選択
- Space: ジャンプ
- Shift: ダッシュ
- R: セッションリセット
- F: 自由練習モードとチャレンジモードの切替
- 1: 静止ターゲットモード
- 2: 移動ターゲットモード
- 3: ポップアップターゲットモード
- 4: ミックスモード
- Q / E: 難易度を下げる / 上げる
- Tab: 統計パネル表示切替
- Esc: ポインターロック解除
- C: クロスヘア種類切替

ゲームモード:
1. 自由練習モード
   - 制限時間なし
   - ターゲットが継続的に出現する
   - 命中率、平均反応時間、コンボをリアルタイム表示する
   - Rで統計をリセットできる

2. 制限時間チャレンジ
   - 30秒または60秒のタイマーを用意する
   - 時間内にどれだけ高スコアを取れるかを測定する
   - 終了時に結果パネルを表示する
   - 結果にはスコア、命中率、平均反応時間、最大コンボ、ミス数を表示する

3. 静止ターゲットモード
   - 的がランダムな位置に静止して出現する
   - 命中または一定時間経過で次の的に切り替わる

4. 移動ターゲットモード
   - 的が左右または上下に滑らかに移動する
   - 移動速度は難易度に応じて変化する
   - 移動は delta time ベースで滑らかにする

5. ポップアップターゲットモード
   - 的が短時間だけ出現する
   - 出現から命中までの反応時間を測定する
   - 一定時間内に撃てなかった場合はミスとして扱う

6. ミックスモード
   - 静止、移動、ポップアップの的がランダムに出現する
   - 難易度に応じて出現間隔、サイズ、移動速度、表示時間を変える

スコア・統計仕様:
- 命中数
- ミス数
- 命中率
- 平均反応時間
- 直近反応時間
- スコア
- コンボ数
- 最大コンボ数
- 1分あたりの命中数
- 現在の難易度
- 現在のモード
- 残り時間
- FPS

スコア計算例:
- 命中: +100点
- コンボ継続: 追加ボーナス
- 反応時間が短いほど加点
- ミス: コンボリセット
- 時間切れで消えたポップアップターゲット: ミス扱い

難易度仕様:
- Easy / Normal / Hard / Expert の4段階
- 難易度によって以下を変える:
  - ターゲットサイズ
  - ターゲット出現間隔
  - ターゲット表示時間
  - 移動ターゲットの速度
  - 同時出現ターゲット数
- 現在の難易度は HUD に表示する
- 難易度変更後、すぐに挙動へ反映する

HUD / UI 仕様:
- 中央にクロスヘアを表示する
- 右上に FPS を表示する
- 左上に現在モード、難易度、残り時間を表示する
- 下部にスコア、命中率、コンボ、平均反応時間を表示する
- 右側に詳細統計パネルを表示する
- 操作ヒントを画面下または開始時オーバーレイに表示する
- ポインターロック前には「クリックして開始」オーバーレイを表示する
- 結果パネルにはリトライボタン、モード切替ボタンを表示する
- リサイズ後も HUD が重なりすぎず、文字が読めること

ビジュアル仕様:
- スポーツ的・SF的な清潔感のある訓練場にする
- ターゲットは非人型で、円形、リング、キューブ、ホログラム板などにする
- ターゲットは見やすく、背景と十分に区別できるようにする
- 命中時は小さなパーティクル、リング拡散、発光フェードなどの視覚効果を入れる
- ミス時はクロスヘアやHUDに短いフィードバックを入れる
- 移動時や視点変更時にカメラが過度に揺れないようにする
- 全体として滑らかな操作感と描画を重視する
- 低〜中スペック環境でも動くよう、過度なポリゴン数や重い処理を避けること

実装方針:
- 可能であれば Vite + TypeScript + three.js 構成にしてください
- 構成は任せますが、GitHub Pages のサブパス公開で壊れないようにしてください
- Vite の base path を GitHub Pages のリポジトリ名に合わせて設定してください
- アセット参照、公開パス、ビルド設定を Pages 前提で調整してください
- 外部アセットに依存しすぎず、訓練場、障害物、ターゲット、HUD は基本的に three.js と CSS で生成してください
- シミュレーション更新は delta time ベースにしてください
- 入力処理、プレイヤー制御、ターゲット生成、スコア管理、HUD更新をできるだけモジュール分割してください
- Playwright で検証しやすいように、主要なHUD要素やボタンには data-testid を付けてください
- クリック命中判定には Raycaster を使ってください
- ポインターロックが使えない環境でも、最低限のクリック操作やUI確認ができるようにしてください
- GitHub Pages への公開は CI/CD で行ってください
- GitHub Actions などを使い、main ブランチへの push を契機に build と deploy が自動で走るようにしてください
- Pages 公開に必要な workflow、設定ファイル、デプロイ設定をリポジトリに含めてください
- 手動作業前提にせず、リポジトリを clone した後でも CI/CD で再現可能な状態にしてください

作業手順:

1. QA inventory を先に作成する
   - ユーザー要求
   - 実装対象
   - 完了報告で主張する内容
   をそれぞれ検証可能な項目に分解する
   - functional QA と visual QA を分離する
   - Playwrightで確認可能な項目と、目視評価が必要な項目を分ける

2. GitHub リポジトリを新規作成する
   - 適切な public リポジトリを作る
   - D:\Prj 配下で作業開始する
   - README、ライセンス、基本設定を含める

3. ローカル実装を行う
   - 必要な依存を導入する
   - dev server を継続セッションで起動する
   - 127.0.0.1 のURLを Playwright で開く
   - 初期表示にエラーがないことを確認する

4. 反復実装を行う
   - 同じ Playwright セッションを維持する
   - コード変更後は reload で確認する
   - 主要コントロールをすべて実操作で確認する
   - reversible な状態変化は往復確認する
   - モード切替、難易度変更、リセット、統計更新、リサイズを確認する
   - ターゲット命中、ミス、時間切れ、コンボ継続、コンボリセットを確認する

5. functional QA を実施する

   以下を Playwright で実操作して確認してください。

   初期表示:
   - アプリがエラーなく起動する
   - クリックして開始オーバーレイが表示される
   - 訓練場、ターゲット、HUD、クロスヘアが表示される
   - FPS が更新される
   - 初期モードと難易度が表示される

   操作:
   - WASDで移動できる
   - マウス移動で視点変更できる
   - Spaceでジャンプできる
   - Shiftでダッシュできる
   - Rでセッションをリセットできる
   - Tabで統計パネルを表示 / 非表示できる
   - Cでクロスヘア種類を切り替えられる
   - Escでポインターロックを解除できる

   ターゲット:
   - 左クリックでターゲットを命中できる
   - 命中時にターゲットが消える、または次のターゲットへ更新される
   - 命中数が増える
   - スコアが増える
   - コンボが増える
   - ミス時にミス数が増える
   - ミス時にコンボがリセットされる
   - ポップアップターゲットの時間切れがミスとして扱われる

   モード:
   - 1キーで静止ターゲットモードに切り替わる
   - 2キーで移動ターゲットモードに切り替わる
   - 3キーでポップアップターゲットモードに切り替わる
   - 4キーでミックスモードに切り替わる
   - Fで自由練習モードとチャレンジモードを切り替えられる
   - チャレンジモードでタイマーが減る
   - チャレンジ終了時に結果パネルが表示される

   難易度:
   - Qで難易度が下がる
   - Eで難易度が上がる
   - 難易度変更がHUDに反映される
   - 難易度によりターゲットサイズ、速度、表示時間などが変わる

   統計:
   - 命中数が表示される
   - ミス数が表示される
   - 命中率が表示される
   - 平均反応時間が表示される
   - 直近反応時間が表示される
   - スコアが表示される
   - コンボ数が表示される
   - 最大コンボ数が表示される
   - 1分あたりの命中数が表示される
   - FPSが表示される

   リサイズ:
   - 横長画面にリサイズしても崩れない
   - 縦長画面にリサイズしても崩れない
   - canvas のアスペクト比が破綻しない
   - HUD が大きく重ならない
   - リサイズ後も操作できる

6. visual QA を実施する

   以下を Playwright のスクリーンショットと目視で確認してください。

   初期表示:
   - 訓練場らしい見た目になっている
   - ターゲットが背景と区別しやすい
   - クロスヘアが中央にあり視認しやすい
   - HUDのテキストが読みやすい
   - 画面がごちゃつきすぎていない

   操作中:
   - 移動が滑らかに見える
   - 視点変更が不自然にカクつかない
   - ジャンプ後に自然に着地する
   - ダッシュ時に速度変化が分かる
   - カメラが過度に揺れない

   ターゲット:
   - 静止ターゲットが見やすい
   - 移動ターゲットが滑らかに動く
   - ポップアップターゲットの出現・消滅が分かりやすい
   - 命中エフェクトが分かりやすい
   - ミス時のフィードバックが分かりやすい

   UI:
   - モード表示が分かりやすい
   - 難易度表示が分かりやすい
   - 統計パネルが読みやすい
   - 結果パネルが読みやすい
   - 操作ヒントが邪魔になりすぎない
   - HUD と3Dビューが重なりすぎない

   リサイズ:
   - 横長画面で崩れない
   - 縦長画面で崩れない
   - 小さい画面でも主要UIが操作可能
   - clipping / overflow がない

7. exploratory pass を行う
   - 30〜90秒程度、実際に遊ぶように確認する
   - 静止、移動、ポップアップ、ミックスの各モードを試す
   - 難易度を変更しながらターゲットを撃つ
   - 自由練習とチャレンジモードの両方を試す
   - 違和感、誤判定、視認性の低さ、パフォーマンス低下、ちらつき、操作しづらさがあれば修正する

8. GitHub Pages 用の CI/CD を構築する
   - GitHub Actions で build と deploy を自動化する
   - main ブランチへの push で GitHub Pages が更新されるようにする
   - Pages 公開に必要な設定をリポジトリに含める
   - Vite の base path を GitHub Pages のサブパスに対応させる
   - 手動作業前提にせず、リポジトリを clone した後でも CI/CD で再現可能な状態にする

9. GitHub Pages にデプロイする
   - 必要な変更を commit / push する
   - CI/CD が正常に完走することを確認する
   - GitHub Pages の公開URLを取得する

10. 公開版 QA を実施する
   - GitHub Pages のURLを Playwright で開く
   - ローカル確認とは別に公開版でも確認する
   - 初期表示、移動、視点変更、ターゲット命中、ミス、モード切替、難易度変更、HUD表示を確認する
   - アセット読込、base path、公開環境での表示崩れを確認する
   - 公開版で問題があれば修正して再度 push し、CI/CD 経由で再デプロイする

11. README を整備する
   - README の先頭付近に、アプリの実スクリーンショットをヘッダー画像として掲載する
   - ヘッダー画像は、訓練場、ターゲット、クロスヘア、HUD、スコア表示が伝わる代表的なプレイ中スクリーンショットにする
   - README には以下を記載する:
     - アプリ概要
     - 安全性・表現方針
     - 主な機能
     - 操作方法
     - ローカル起動方法
     - GitHub Pages の公開URL
     - CI/CD によるデプロイ方法の概要
     - QA で確認した内容
     - スクリーンショット

12. 最後に結果を報告する
   - GitHub リポジトリ名
   - GitHub リポジトリ URL
   - GitHub Pages 公開 URL
   - 実装した機能
   - 構築した CI/CD の概要
   - ローカルで確認済みの項目
   - 公開版で確認済みの項目
   - Playwright で確認した操作
   - visual QA で確認した画面状態
   - 未確認項目
   - 残課題
   - README に使ったスクリーンショットのパス

重要:
- 最終報告では、実際に確認していないことを確認済みと書かないでください
- Playwright で確認した内容と、目視確認のみの内容を分けて報告してください
- CI/CD が失敗した場合は、原因と対応状況を明記してください
- GitHub Pages の公開 URL が表示できない場合は、そこまでに完了した内容と未完了理由を明記してください
- 実在の武器・対人戦・軍事訓練を想起させる表現ではなく、スポーツ的なエイム練習・反応速度トレーニングとして実装してください
- 滑らかな視点操作、明確な命中判定、読みやすいHUD、Playwrightで検証可能な状態を優先してください
